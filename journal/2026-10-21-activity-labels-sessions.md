# 2026-10-21 Activity labels, shimmer, sessions in the sidebar

## Goal

Marushan likes how Claude Code desktop shows what an agent is doing. Bring three things into PandaOS:

1. A short activity line for a group of tool calls while it runs ("Clicking, waiting, capturing page"), the finished label when it is done.
2. Shimmer only on what is running right now. Finished items never shimmer.
3. A second chat on the same topic appears in the sidebar as a child row under its workspace and opens as a tab in that workspace. No new workspace, no new worktree.

## Findings from Claude desktop (REA, 2026-10-21)

Target: `/Applications/Claude.app` 3.1623.0 on the Mac, `app.asar` sha256 prefix `760e7cbb6f861f0b`. The Code tab UI is not in the asar; it is the claude.ai web bundle served from `assets-proxy.anthropic.com/claude-ai/v2/assets/v1/`. Bundles were taken from the URLs in the app's V8 code cache and downloaded from the public asset host.

Observed (static code, not runtime):

- Activity text is deterministic, not generated by a model. `shared-m-1-CiheqC_D.js` (sha256 prefix `208aa9777ed1b819`) holds tables of `{running, done}` pairs per tool or per tool action, for example `screenshot: {running: "Capturing page", done: "Captured page"}`, `left_click: {running: "Clicking", done: "Clicked"}`. Unknown browser tools fall back to `{running: "Using the browser", done: "Used the browser"}`.
- A batch of actions is joined by `OA()`: distinct labels in order, at most 3 (`sR = 3`), first label kept as is, the rest lowercased, joined with `", "`, overflow as ` +N`. That is exactly "Clicking, waiting, capturing page" and the "+3" next to the thumbnails.
- The running or done variant is picked by the tool's own `done` flag, not by the agent state.
- Shimmer state comes from `D7()` in the same bundle: `thinking` before the stream, `shimmer` while a tool runs, `writing` while text streams, otherwise `idle`. The text shimmer itself is an overlay span with a 105 degree gradient and `animate-[cds-shimmer-text-shine_3s_linear_infinite]`, hidden for `motion-reduce` and `forced-colors` (`shared-16-dpqpLU4u.js`, prefix `b001625191cc2121`).
- The Claude Code CLI 2.1.296 also emits `tool_use_summary` messages. Their label comes from a small model call with this system prompt (verbatim): "Write a short summary label describing what these tool calls accomplished. It appears as a single-line row in a mobile app and truncates around 30 characters, so think git-commit-subject, not sentence. Keep the verb in past tense and the most distinctive noun. Drop articles, connectors, and long location context first." Input: tool name, input and output each cut to 300 chars, plus the first 200 chars of the last assistant message. The desktop app uses these summaries for its stream bookkeeping (`preceding_tool_use_ids`); the live gerund line comes from the tables above.

Not established: the exact desktop component that renders the group header, and how the claude.ai sidebar decides to nest a session. Those parts were not traced.

Second desktop finding, same build (`index.chunk-XE4x008H.js` and `index.chunk-Cses962f.js` in the asar): the desktop app gives the model its own MCP tools. `update_plan` must say per request whether it is `first_task`, `continuation` or `new_task`; a `new_task` turn starts with `mcp__ccd_session__start_session` and `initiation: "offer"`, which shows the "New session / Do it here" card and waits for the answer. Unsure cases count as `continuation`, because a wrong offer interrupts the user and a wrong continuation only makes the chat longer.

## Implemented

1. Shimmer (`types/stream.ts`): on `turn_completed`, `turn_failed` and `turn_canceled` every agent tool call still `running` becomes `canceled`, plan calls excepted. Hydrated history does the same for calls before the last user message. Root cause, not fixed: the Claude provider emits `canceled` for open calls only on failed or canceled turns (`finishForegroundTurn`), and `flushPendingToolCalls` also clears subagent bookkeeping, so it cannot simply run on completion.
2. Activity line (`tool-calls/activity.ts`): fixed mapping from tool call to a running label, browser tools by action name. A running tool group shows the latest three distinct labels, the rest as `+N`; a finished group keeps "Worked for X, ...". The working footer shows the running tool's label instead of the raw tool name.
3. Session rows: the workspace activity index carries the later root agents of a workspace (at most the three newest); `SidebarSessionRows` renders them under the workspace row in project and status mode and opens the agent tab on press.
4. `start_session` (Paseo MCP tool, agent-scoped): creates a detached root agent in the caller's workspace with the caller's provider, model, thinking and mode. The daemon prompt (`SESSION_SPLIT_INSTRUCTION`) tells agents to ask "New session" or "Do it here" with their question tool first. No new client card: the existing question card carries the choice.
